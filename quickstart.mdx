---
title: "Quickstart"
description: "Create a working Java enterprise application with a full CRUD interface using UDA in under 5 minutes."
---

This guide walks you through creating a new UDA project from scratch, generating a CRUD entity, and running the application. By the end, you will have a running web application with a fully functional maintenance interface.

<Info>
  This guide assumes you have completed the [installation](/installation) and have Eclipse open with the UDA plugin active.
</Info>

<Steps>
  <Step title="Open Eclipse with the UDA plugin">
    Launch Eclipse using the UDA bundle or your manually configured Eclipse instance. Confirm the UDA plugin is active by going to **Help > About Eclipse IDE > Installation Details** and verifying the UDA entry is present.

    You should also see **UDA** entries in the **File > New > Other** wizard list. If they are missing, check the Eclipse error log under **Window > Show View > Error Log** and re-verify the [installation steps](/installation).
  </Step>

  <Step title="Create a new UDA project">
    1. Go to **File > New > Other** and expand the **UDA** category.
    2. Select **UDA Project** and click **Next**.
    3. Fill in the project details in the wizard:

    | Field | Example value | Description |
    |-------|---------------|-------------|
    | **Group ID** | `com.example` | Maven group identifier for your organization |
    | **Artifact ID** | `myapp` | Maven artifact name; also used as the base project name |
    | **Package name** | `com.example.myapp` | Root Java package for generated source files |
    | **Version** | `1.0.0-SNAPSHOT` | Initial project version |

    4. Click **Finish**. The wizard generates the full project structure.

    <Note>
      The wizard may take a minute on first run — it downloads Maven dependencies and sets up the project modules.
    </Note>
  </Step>

  <Step title="Understand the generated project structure">
    UDA generates a multi-module Maven project following a standard enterprise architecture. The top-level structure looks like this:

    <Tree>
      <Tree.Folder name="myapp" defaultOpen>
        <Tree.Folder name="myappEar" defaultOpen>
          <Tree.File name="pom.xml" />
        </Tree.Folder>
        <Tree.Folder name="myappEjb" defaultOpen>
          <Tree.File name="pom.xml" />
          <Tree.Folder name="src/main/java">
            <Tree.File name="(services, DAOs, entities)" />
          </Tree.Folder>
        </Tree.Folder>
        <Tree.Folder name="myappWar" defaultOpen>
          <Tree.File name="pom.xml" />
          <Tree.Folder name="src/main/java">
            <Tree.File name="(controllers, DTOs)" />
          </Tree.Folder>
          <Tree.Folder name="src/main/webapp">
            <Tree.File name="(JSP views, RUP components, static assets)" />
          </Tree.Folder>
        </Tree.Folder>
        <Tree.File name="pom.xml" />
      </Tree.Folder>
    </Tree>

    Each module has a distinct responsibility:

    - **EAR module** — Packages the application for deployment to a Java EE application server. Contains the assembly descriptor.
    - **EJB module** — Holds the business layer: entities, services, DAOs, and Spring configuration for persistence and transactions.
    - **WAR module** — Holds the web layer: Spring MVC controllers, DTOs, JSP views, and the RUP frontend components.

    <Note>
      Spring MVC is configured automatically. The `applicationContext.xml` files in the EJB and WAR modules wire the component-scan, transaction management, data source, and view resolver.
    </Note>
  </Step>

  <Step title="Generate a CRUD entity with the Maintenance Assistant">
    UDA's Maintenance Assistant wizard generates a complete CRUD interface — controller, service, DAO, entity, DTO, and JSP views — for any domain entity.

    1. Right-click the **EJB module** in the Project Explorer and select **New > Other > UDA > Maintenance**.
    2. In the wizard, provide the entity details:

    | Field | Example value |
    |-------|---------------|
    | **Entity name** | `Usuario` |
    | **Table name** | `T_USUARIO` |
    | **Primary key field** | `id` (Long) |

    3. Add fields using the field editor (for example: `nombre` as `String`, `email` as `String`, `activo` as `Boolean`).
    4. Click **Finish**.

    The wizard generates the following files across both modules:

    - `UsuarioController.java` — Spring MVC controller in the WAR module
    - `UsuarioService.java` / `UsuarioServiceImpl.java` — Service layer in the EJB module
    - `UsuarioDao.java` / `UsuarioDaoImpl.java` — Data access layer in the EJB module
    - `Usuario.java` — JPA entity in the EJB module
    - `UsuarioDto.java` — Data transfer object in the WAR module
    - `usuario.jsp` — Main JSP view with the RUP data table
    - `usuarioForm.jsp` — Maintenance form JSP view
  </Step>

  <Step title="Review the generated controller">
    Open `UsuarioController.java` in the WAR module. The generated controller follows the standard UDA pattern — extending `BaseController` and using Spring MVC annotations:

    ```java
    @Controller
    @RequestMapping("/usuario")
    public class UsuarioController extends BaseController {
        
        @Autowired
        private UsuarioService usuarioService;
        
        @RequestMapping(method = RequestMethod.GET)
        public String index(Model model) {
            return "usuario/usuario";
        }
        
        @RequestMapping(value = "/search", method = RequestMethod.GET)
        @ResponseBody
        public DataTablesOutput<UsuarioDto> search(
                @Valid DataTablesInput input, BindingResult bindingResult) {
            return usuarioService.findAll(input);
        }
    }
    ```

    Key points about the generated code:

    - `BaseController` (from `x38ShLibClasses`) provides common exception handling, logging, and utility methods.
    - The `index` method returns the view path — `usuario/usuario` maps to `WEB-INF/views/usuario/usuario.jsp`.
    - The `search` method powers the RUP data table with server-side pagination and filtering via `DataTablesInput`.
    - Additional CRUD endpoints (`add`, `update`, `delete`) are generated in the full controller — this is an excerpt.
  </Step>

  <Step title="Deploy to a server and verify">
    1. In Eclipse, open the **Servers** view (**Window > Show View > Servers**). If no server is configured, add one (for example, Apache Tomcat or WildFly) using **New > Server**.
    2. Right-click the server and select **Add and Remove**. Move your application's EAR or WAR to the **Configured** column and click **Finish**.
    3. Start the server by right-clicking it and selecting **Start**.
    4. Once the server is running, open a browser and navigate to:

    ```
    http://localhost:8080/myappWar/usuario
    ```

    You should see the generated `Usuario` maintenance interface — a data table with search, add, edit, and delete actions, all powered by the RUP components.

    <Check>
      If the page loads with the data table and toolbar, your UDA setup is working correctly.
    </Check>

    <Warning>
      If you see a blank page or a 404, check that the WAR was deployed correctly and that the Spring MVC dispatcher servlet is mapped to `/` in `web.xml`. Check the server console for any startup errors.
    </Warning>
  </Step>
</Steps>
