UDA's code wizard can generate complete CRUD interfaces from a set of pre-defined **maintenance patterns**. Each pattern combines a set of JSP views, a Spring MVC controller, and the corresponding RUP component configuration.

<Info>
  Patterns are generated by the **Maintenance wizard** inside the UDA Eclipse plugin. Select an entity, choose a pattern, and the wizard produces all server-side and client-side files.
</Info>

---

## Maintenance with form (mantenimiento-formulario)

The most common pattern for managing a single entity. A paginated table lists all records; the user clicks a row to open a separate form view for editing, or clicks **New** to open a blank form.

**Screenshot**

![Maintenance-with-form pattern: table list with a separate edit form](/images/imgwikis/mtoformulario2.0.png)

### UX flow

<Steps>
  <Step title="List view">
    The user lands on `entityList.jsp`. A `rup_table` displays all records with pagination and column sorting. A `rup_toolbar` provides **New**, **Edit**, and **Delete** buttons.
  </Step>
  <Step title="Select a record">
    The user clicks a row (or clicks **Edit** after selecting a row). The table row is highlighted and the **Edit** toolbar button activates.
  </Step>
  <Step title="Form view">
    `entityForm.jsp` is shown (either in-page or as a dialog). A `rup_form` pre-fills the fields with the row data loaded via `GET /entity/{id}`.
  </Step>
  <Step title="Save">
    The form submits via Ajax (`POST /entity` for create, `PUT /entity/{id}` for update). On success, `rup_feedback` shows a confirmation and the table reloads.
  </Step>
  <Step title="Delete">
    Clicking **Delete** with a row selected opens a `rup_dialog` confirmation. Confirmed deletes call `DELETE /entity/{id}`.
  </Step>
</Steps>

### Generated files

| File | Purpose |
|---|---|
| `entityList.jsp` | Table view with toolbar and feedback area |
| `entityForm.jsp` | Create/edit form with validation |
| `EntityController.java` | Spring MVC controller |
| `EntityService.java` / `EntityDao.java` | Service and DAO stubs |
| `entity_i18n.properties` | i18n messages for labels and feedback |

### URL structure

| HTTP method | URL | Action |
|---|---|---|
| `GET` | `/entity` | Render the list view |
| `GET` | `/entity/search` | Fetch table rows (JSON) |
| `GET` | `/entity/{id}` | Load a single record for the form |
| `POST` | `/entity` | Create a new record |
| `PUT` | `/entity/{id}` | Update an existing record |
| `DELETE` | `/entity/{id}` | Delete a record |

### Wizard selection

In the UDA Eclipse plugin, choose:

> **File → New → UDA → Maintenance wizard → Maintenance with form**

## Inline editing (mantenimiento-edición-en-línea)

Cells are edited directly inside the table row — no separate form view is needed. Suitable for simple entities with few fields.

**Screenshot**

![Inline editing pattern: editable cells in the table row](/images/imgwikis/mtoedicionlinea2.0.png)

### UX flow

<Steps>
  <Step title="List view">
    A `rup_table` displays all records. Rows are selectable.
  </Step>
  <Step title="Enter edit mode">
    Double-clicking a row (or clicking **Edit** in the toolbar) switches the row into edit mode. Text fields and select controls appear in place.
  </Step>
  <Step title="Edit cells">
    The user modifies values directly in the row. Tab navigation moves between editable cells.
  </Step>
  <Step title="Save or cancel">
    Clicking **Save** submits the changed row via `PUT /entity/{id}`. Clicking **Cancel** reverts the row to its original values.
  </Step>
</Steps>

### Generated files

| File | Purpose |
|---|---|
| `entityList.jsp` | Table view with inline edit configuration |
| `EntityController.java` | Spring MVC controller (same URL structure as form pattern) |
| `EntityService.java` / `EntityDao.java` | Service and DAO stubs |

### URL structure

Same as the maintenance-with-form pattern — the difference is entirely in the client-side rendering.

### `rup_table` configuration for inline editing

```javascript
$("#entityTable").rup_table({
    url: "/api/entity/search",
    colModel: [
        { label: "Name",   name: "name",   width: 150, editable: true, edittype: "text"   },
        { label: "Status", name: "status", width: 80,  editable: true, edittype: "select",
          editoptions: { value: "A:Active;I:Inactive" } }
    ],
    cellEdit: true,           // Enable cell-level inline editing
    cellsubmit: "remote",     // Submit changes to the server on cell blur
    cellurl: "/api/entity"
});
```

### Wizard selection

> **File → New → UDA → Maintenance wizard → Inline editing**

## Master-detail (mantenimiento-maestro-detalle)

A parent entity (the "master") and a related child entity (the "detail") are displayed on the same page. Selecting a master record filters the detail table.

**Screenshot**

![Master-detail pattern: parent table on top, child table below](/images/imgwikis/mantenimiento-maestro-detalle.png)

### UX flow

<Steps>
  <Step title="Page load">
    The page loads with the master `rup_table` populated and the detail table empty (or showing a placeholder message).
  </Step>
  <Step title="Select a master record">
    The user clicks a row in the master table. An `onSelectRow` event fires.
  </Step>
  <Step title="Detail table reloads">
    The detail `rup_table` reloads with a filter parameter set to the selected master record's ID: `GET /detail/search?masterId={id}`.
  </Step>
  <Step title="CRUD on detail">
    The detail toolbar activates. The user can add, edit, or delete child records. All operations include the master ID as a parameter.
  </Step>
</Steps>

### Generated files

| File | Purpose |
|---|---|
| `masterDetailPage.jsp` | Single page containing both tables |
| `MasterController.java` | Spring MVC controller for the master entity |
| `DetailController.java` | Spring MVC controller for the detail entity |

### URL structure

**Master entity**

| HTTP method | URL | Action |
|---|---|---|
| `GET` | `/master/search` | Fetch master rows |
| `POST` | `/master` | Create master record |
| `PUT` | `/master/{id}` | Update master record |
| `DELETE` | `/master/{id}` | Delete master record |

**Detail entity**

| HTTP method | URL | Action |
|---|---|---|
| `GET` | `/detail/search?masterId={id}` | Fetch detail rows filtered by master |
| `POST` | `/detail` | Create detail record (body includes `masterId`) |
| `PUT` | `/detail/{id}` | Update detail record |
| `DELETE` | `/detail/{id}` | Delete detail record |

### Wiring the tables in JavaScript

```javascript
// Master table
$("#masterTable").rup_table({
    url: "/api/master/search",
    colModel: [ /* ... */ ],
    onSelectRow: function(rowId) {
        // Reload detail with the selected master ID
        $("#detailTable").rup_table("setFilter", { masterId: rowId });
        $("#detailTable").rup_table("reload");
    }
});

// Detail table — initially empty
$("#detailTable").rup_table({
    url: "/api/detail/search",
    colModel: [ /* ... */ ],
    loadOnStartup: false,
    toolbar: { formEdit: true }
});
```

### Wizard selection

> **File → New → UDA → Maintenance wizard → Master-detail**

## Search table (tabla con búsqueda)

A dedicated filter form sits above the data table. The user fills in search criteria and submits the form to filter the table results. No create/edit/delete is required — this pattern is for read-only or report-style views.

**Screenshots**

![Search table pattern: filter form above the data table](/images/imgwikis/tabla-busqueda.png)

![Search table with active filters applied](/images/imgwikis/tabla-buscar.png)

### UX flow

<Steps>
  <Step title="Page load">
    The page renders with a filter form and an empty (or default-loaded) `rup_table`.
  </Step>
  <Step title="Enter filter criteria">
    The user fills in one or more filter fields (text inputs, selects, date ranges).
  </Step>
  <Step title="Submit">
    Clicking **Search** serializes the form and passes the values as query-string parameters to the table's URL: `GET /entity/search?name=foo&status=A`.
  </Step>
  <Step title="Results displayed">
    The `rup_table` re-renders with the filtered rows. Pagination resets to page 1.
  </Step>
  <Step title="Clear filters">
    Clicking **Clear** resets all filter fields and reloads the unfiltered table.
  </Step>
</Steps>

### Generated files

| File | Purpose |
|---|---|
| `entitySearch.jsp` | Search form + results table |
| `EntityController.java` | Spring MVC controller |

### URL structure

| HTTP method | URL | Action |
|---|---|---|
| `GET` | `/entity` | Render the search page |
| `GET` | `/entity/search` | Fetch filtered rows (JSON); all filter fields sent as query parameters |

### Wiring the filter form to the table

```javascript
// Filter form
$("#filterForm").rup_form({
    ajaxSubmit: false,   // Prevent default submit; the table handles it
    submitHandler: function() {
        $("#resultsTable").rup_table("reload");
    }
});

// Results table — reads filter values from the form automatically
$("#resultsTable").rup_table({
    url: "/api/entity/search",
    filterForm: "#filterForm",
    colModel: [
        { label: "Name",   name: "name",   width: 200 },
        { label: "Status", name: "status", width: 80  },
        { label: "Date",   name: "date",   width: 100 }
    ],
    loadOnStartup: false
});
```

### Wizard selection

> **File → New → UDA → Maintenance wizard → Search table**

## Choosing a pattern

| Pattern | Best for |
|---|---|
| Maintenance with form | Entities with many fields or complex validation |
| Inline editing | Simple entities with few short fields |
| Master-detail | Parent–child relationships (e.g., order + order lines) |
| Search table | Read-only reporting or lookup screens |

<Tip>
  All patterns can be customized after generation. The wizard output is a starting point, not a locked-down scaffold. You can mix pattern elements — for example, add a search form to a maintenance-with-form screen by setting `filterForm` on the `rup_table`.
</Tip>
